# 赛后站点发布（本地试用版）

发布流程在编辑器的文件菜单 → **赛后发布…**（快捷键 Alt+Shift+P，Esc 关闭）。运动员页面为独立的 `/viewer`；专用发布构建也将网站首页设为运动员页面。现有编辑器正常构建和线上部署配置不变。

## 准备内容

1. 使用线路设计模式保存的原有 JSON 比赛文件即可：在发布设置中点击“导入线路设计 JSON”，不会替换当前编辑器内容。也可直接使用编辑器当前打开的比赛。文件需要包含节点、合法连线和赛程；地图建议随 JSON 嵌入保存。未嵌入时，选择赛程后可在对应地图处补充本地 PDF / 图片，不会使用其他比赛的当前地图。
2. 打开发布设置，明确勾选公开赛程。自定义路线留在编辑器中。地图必须在本地可读取并嵌入包中。
3. 设置稳定比赛标识与发布版本（仅英文字母、数字、下划线、连字符）。比赛标识在每次更新时保持相同，发布版本必须更新。
4. 点击“加入 / 更新公开包”。可以导入之前下载的发布包保留已公开历史比赛，再加入当前比赛。
5. 选择固定入口的当前比赛。取消某比赛“公开”即将其从新部署中撤下；“暂停固定入口”仅暂停首页，仍公开的历史链接继续可用。若要暂停所有访问，同时取消所有比赛的公开状态。
6. 导入线路设计 JSON 并选择赛程后，可直接点击“预览运动员页面”，无需先加入公开包；在当前标签页检查已选择的赛程和地图。预览包仅存入当前浏览器会话，不上传文件、不修改公开清单；当前标签页刷新可恢复预览，关闭标签页后预览链接会失效；预览链接不能跨设备分享，其他浏览器没有这份会话数据。大地图若超过浏览器会话存储额度，会明确提示缩小地图。进入预览前可下载发布包备份当前设置。
7. 下载 `publication-bundle.json`。发布设置保存在这个文件内；关闭对话框后通过导入恢复。归档数据需保留旧包备份，新的公开包不会携带归档内容。

本地 JSON 发布包包含选定的公开内容，不包含托管账号凭证。每个赛段自动计算最多 6 条候选路线，提供长度、时间和难度比较。

## 生成上传目录

在仓库根目录执行专用构建：

```bash
pnpm --filter web build:published
pnpm --filter web package:published /绝对路径/publication-bundle.json /绝对路径/新的上传目录
```

打包程序读取 `apps/web/out`，要求专用发布构建标记，拒绝普通编辑器构建和已存在的目标目录。只复制运动员 HTML、静态脚本/样式/字体、PDF Worker、图标与本次公开比赛数据；不复制示例库、编辑器页面、Service Worker、源代码映射或旧部署目录。每次创建新的上传目录，确保归档比赛不残留。

发布清单位于 `published/manifest.json`，内容包按比赛标识与版本放在 `published/events/`。固定入口读取当前比赛；历史链接为 `/viewer?event=比赛标识`。打包器检查单文件 25 MiB 限制；超限时需减小地图文件。文件数量较多时会提示使用 Wrangler，而非控制台拖放。

## 本地检查与上传

先使用任意本地静态 HTTP 服务器预览上传目录，检查首页、历史链接、地图、候选路线、个人路线保存和 GPX。不要用文件协议直接打开 HTML。然后将**上传目录内容**通过自己的 Cloudflare Pages Direct Upload 更新同一个项目。必须发布新目录的完整快照，不能将新文件合并到保留旧事件的目录。

`_headers` 为 Cloudflare 配置清单与入口缓存重验证；迁移到其他托管平台时须配置对应缓存规则。归档后还应验证旧内容地址不再返回比赛文件，并清除托管缓存。旧部署及预览快照可能仍有独立网址；如需撤回公开内容，还要在托管控制台删除这些旧部署/预览并验证地址失效。已下载的数据无法收回。

本功能未自动上传或修改生产站点。正式部署前仍需验证中国大陆目标网络、手机与微信浏览器，并使用选定版本 QuickRoute / Headcam O 实测 GPX 地图对齐与视频同步。合成坐标用于地图排版，不能表示真实 GPS 位置。

## 开发验证

```bash
pnpm typecheck
pnpm --filter @indoor-o-route-analysis/core exec vitest run --maxWorkers=1
pnpm --filter web test:run
pnpm --filter web exec playwright test -c playwright.publication.config.ts
```

浏览器测试使用独立回环端口 18143，拒绝复用已有服务，覆盖桌面与手机视口。路径搜索性能回归建议串行运行，避免并发构建争用 CPU。PDF 主模块和 Worker 都由本地 `postinstall` 准备，不依赖外部 CDN。

2026-10-19 验收记录：全仓库串行测试（`pnpm exec turbo test:run --concurrency=1 -- --maxWorkers=1`）601 项通过，桌面与手机端 Playwright 测试 10 项通过。专用静态构建及其上传目录已在本地 HTTP 服务实测地图/PDF 显示、Worker 路线计算、GPX 下载、刷新恢复和历史比赛隔离。开发使用独立 Git worktree；未执行线上部署。QuickRoute / Headcam O 实际导入与大陆网络访问仍需在目标环境验收。

## 运动员路线探索

界面沿用 Route Builder 的黑底、紫色选中态和难度徽标。选择赛段后自动显示最多 6 条候选路线，点击行查看地图；卡片显示路线编码、simple / fewest floors / shortest 自动标签、距离、爬升、时间、难度、分支数、决策点数、楼梯数和前段重复比例。默认速度为 3 m/s，时间按秒四舍五入。候选生成与 0.2.5-test.2 一致，优先展示简单、跨层最少、最短方案，并合并相近路线；各赛段比较基准使用真正最短路线。手机单指拖动平移、双指缩放与移动，轻点节点添加途经点。帮助窗口列出操作和快捷键。

本轮验证：64 项前端测试、13 项桌面/手机浏览器测试通过，触屏测试使用真实浏览器触摸事件覆盖平移和双指缩放。核心测试 458 项首轮通过，另一个既有 2 秒性能阈值用例在无并发负载下复测通过（1.75 秒）。王府井 7 组别、113 赛段共验证 661 条候选；首段与 Route Builder 对齐为 93 m、0:18、D37。

2026-10-20 更新：同步 0.2.5-test.2 候选算法及参数卡片，运动员界面 Course 统一显示为“线路”。王府井最新 JSON 使用新发布版本，固定预览入口不变。

本轮验证：核心 473 项、前端 65 项、浏览器 13 项通过（桌面跳过 1 项仅触屏测试），全仓库类型检查通过。新增真实 JSON 回归覆盖第 3→4 段的编码、排序、爬升、难度和重复比例。
